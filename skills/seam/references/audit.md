# Seam Audit

Audit the complete seam and exact candidate. A diff is the starting map, not
the full review surface.

## Independence

Prefer an auditor that did not implement the candidate. Auditors are read-only
on implementation and acceptance. An auditor that repairs loses independence
for that repair.

If independent execution is unavailable, perform the best read-only review
possible and state the residual independence risk.

## Intake

Bind:

- candidate/base identity;
- seam outcome and interface;
- authority/constraints;
- changed and untracked files;
- write surface and unrelated dirty state;
- callers, adapters, composition points;
- expected tests/live boundaries/resources;
- prior findings and dependency halts.

Stop if the subject or write boundary is ambiguous enough to make findings
unattributable.

## Code Quality audit

Inspect:

- interface completeness and depth;
- deletion/variation results;
- one coherent change vector and owner;
- all affected callers and hidden bypasses;
- dependency direction and concrete construction;
- provider/error/type leakage;
- validation, authorization, no-write guarantees;
- state, transactions, idempotency, timeout/cancellation, retry and cleanup;
- naming, locality, public exports, dead paths and unnecessary code;
- platform resolution and client/server separation;
- tests at the faithful interface;
- scope/write-surface compliance.

Question every abstraction with no current behavioral demand. Recommend the
smallest repair at the highest shared owner.

## QA audit

Exercise:

- representative success through the public seam;
- ordinary rejection and smallest adversarial counterexamples;
- real database/process/filesystem/protocol/provider/device/browser boundary
  whose behavior is claimed;
- direct rendered interaction for UI behavior;
- duplicate/replay/concurrency and stale-state paths;
- provider interruption, timeout, cancellation, restart/reconciliation;
- failure-path cleanup and zero unexpected resource delta;
- stable scenario/test identity and nonzero selection/execution.

Do not accept screenshots, status text, authored reports, or an exit code alone
as proof.

## False-green attacks

Look specifically for:

- wrong target/path or zero selected tests;
- unloaded/no-op/unawaited assertions;
- API/data proxy standing in for UI behavior;
- any listener/body accepted as the intended server;
- mocks encoding a provider contract not checked against reality;
- stale generated output bypassing source authority;
- help/error output exiting zero;
- ambient process/resource changes masking an owned leak;
- a test-only seam production callers bypass;
- evidence generated by rewriting the evidence being verified;
- directory/glob/status claims without immutable file content.

## Findings

Continue after findings where safe and publish one exhaustive ledger. Each
finding has:

```text
stable ID
blocking or advisory severity
interface/invariant violated
file/line/command/runtime evidence
observable impact
root cause
smallest authorized repair surface
exact reproduction/verification
owner and disposition
```

Deduplicate shared root causes; do not count symptoms as separate fixes. A
blocking finding prevents acceptance. Advisory findings do not silently become
required scope unless the owner authorizes them.

## Three-phase audit packet

For Base candidates, join Code Quality and QA into one immutable packet:

- Base candidate identity;
- report/artifact digests;
- every open finding;
- frozen behavior/locked greens;
- repair surface and affected validators;
- resource state and residual risk.

This packet is the only input boundary for Final Polish. Do not send the
implementer broad audit conversation or desired implementation details.

## Final Polish verification

After repair:

1. bind the new candidate and exact finding delta;
2. rerun each finding reproduction and directly affected public behavior;
3. verify locked behavior did not weaken;
4. inspect changed callers/adapters and cleanup;
5. close, regress, or keep open every finding;
6. avoid a whole-seam rerun unless the repair broadened the risk surface.

The implementer does not close its own finding. Remaining blocking findings
halt the seam rather than trigger unlimited retries.

## Audit output

Report:

```text
subject/candidate
independence declaration
surface inspected
behavior/resource evidence
findings ledger
claims-versus-current-state discrepancies
blocking/advisory totals
open risks
one next authorized action
completion marker
```

Do not implement repairs or issue external approval beyond the audit role.
