# BATDD Worker Contract

This is the compact Worker hot path compiled from the canonical Agent Wiki standards and the repository `TESTING.md`. It may narrow an assignment but may not weaken its sources.

## Activation

On implementation or repair:

1. Invoke the global `$batdd` skill.
2. Validate `.agents/batdd/profile.json` and the named assignment envelope against their schemas.
3. Confirm skill and standard versions, role, completion scope, required layers, write surface, base/candidate revisions, and stop boundary.
4. Create the runtime-native BATDD plan before the first product write. Do not ask permission to self-organize.

Escalate to repository `TESTING.md` and canonical Wiki doctrine only for the conditions listed in `profile.json`.

## Native plan

Keep plan state concise and evidence-driven:

1. Hydrate authority, profile, assignment, graph, and dirty state.
2. Compile a basic-plus-adversarial Green Contract.
3. Prove every required new or changed L1/L2/L3 row meaningfully RED.
4. Freeze the contract by ID/hash.
5. Implement fidelity-ordered GREEN.
6. Run affected standing, live, cleanup, and resource-delta gates.
7. Register evidence and inspect scoped state.
8. Stop at the assignment boundary without self-certifying.

Exactly one plan item is in progress. File existence, terminal quiet, and self-report do not advance plan state.

## Vertical slice

`vertical-slice` is the default. Every required L1/L2/L3 layer must be GREEN before `READY-FOR-AUDIT`.

An N/A layer remains visible and requires a profile-backed reason. A missing runner or target is a blocker, not N/A.

A `layer` assignment may complete its layer only and must declare `mayReportFeatureComplete: false`.

## Testing independence

- Native runners own L1 and L2; Cucumber owns L3 behavior.
- Cucumber steps do not invoke or import L1/L2 entrypoints.
- Layers may share only framework-neutral support.
- Every asynchronous action/assertion is awaited or returned.
- Every `Then` asserts an observable outcome.
- UI claims require a UI-capable surface.
- Required collectors reject zero selection, pending/undefined/ambiguous steps, no-op bindings, and wrong-target success.

## RED, freeze, GREEN

- Basic coverage precedes an adversarial disproof pass.
- Every new or changed contract row demonstrates intended missing-behavior RED before product implementation.
- Harness, syntax, dependency, binding, or zero-test failures are defective RED.
- Freeze identities, semantics, assertions, values, negative guarantees, target vocabulary, artifacts, and cleanup before GREEN writes.
- Run affected L1 unit, L1 integration, L2 integration, L2 E2E, then L3.
- Preserve locked greens and repair only failed or transitively affected seams.

## Evidence and stop

Record intended project, target, layer, runtime, working directory, immutable revisions, nonzero selection or explicit N/A, exit code, duration, decisive output, artifacts, and resource delta.

An implementer reports evidence and stops at `READY-FOR-AUDIT`. Fresh verification and authorized judgment determine shippability.
